# Gym Tracking App with Streamlit, Docker, and PostgreSQL

Build a simple gym tracking application using Streamlit, Docker, and PostgreSQL that allows users to log exercises and visualize progress over time.

## Summary
Create a gym tracking app with Streamlit frontend, PostgreSQL database backend, both running in Docker containers, enabling users to log multiple exercises per workout session and visualize volume progress over time.

## Additional Components Needed
- **Python dependencies**: streamlit, psycopg2 (PostgreSQL adapter), pandas (data handling), plotly (interactive charts)
- **Docker Compose**: To orchestrate Streamlit and PostgreSQL containers
- **Database schema**: Workout sessions table with related exercises table for multiple exercises per session
- **Streamlit app structure**: Session-based data entry forms and volume visualization pages
- **Environment configuration**: For database connection credentials

## Implementation Steps

1. **Create project structure**
   - Create `app/` directory for Streamlit application
   - Create `app/requirements.txt` for Python dependencies
   - Create `app/streamlit_app.py` for main application code
   - Create `docker-compose.yml` for container orchestration
   - Create `Dockerfile` for Streamlit container
   - Create `.env` file for environment variables

2. **Set up PostgreSQL database**
   - Configure PostgreSQL service in docker-compose.yml
   - Create database initialization script for table schema
   - Define table structure:
     - `workout_sessions` table: id, session_date, notes
     - `exercises` table: id, session_id, exercise_name, reps, sets, pounds
   - Create foreign key relationship between exercises and sessions

3. **Implement Streamlit application**
   - Database connection setup using psycopg2
   - Session-based data entry:
     - Create new workout session with date
     - Add multiple exercises to each session (exercise name, reps, sets, pounds)
     - Submit session with all exercises to PostgreSQL
   - Data retrieval queries for visualization
   - Create volume-focused charts using plotly:
     - Total volume over time (sum of sets × reps × pounds)
     - Volume progression by exercise
     - Session comparison charts

4. **Configure Docker setup**
   - Create Dockerfile for Streamlit app (Python base image, install dependencies)
   - Configure docker-compose.yml with:
     - Streamlit service (expose port 8501)
     - PostgreSQL service (expose port 5432)
     - Network and volume configuration
   - Set environment variables for database connection

5. **Add data persistence**
   - Configure Docker volume for PostgreSQL data
   - Ensure database persists across container restarts

## Technical Considerations
- **Database security**: Use environment variables for credentials, not hardcode in app
- **Data validation**: Add basic input validation for reps, sets, pounds (positive numbers)
- **Session management**: Implement session-based entry for multiple exercises per workout
- **Volume calculation**: Volume = sets × reps × pounds for each exercise and session totals
- **Chart interactivity**: Use plotly for interactive volume charts with exercise filtering
- **Error handling**: Graceful error messages for database connection issues
- **Container networking**: Ensure Streamlit can connect to PostgreSQL container
- **Append-only design**: No edit/delete functionality, simplifying the data model

## Token Usage Optimization Rules
- **Modular code structure**: Create reusable functions for database operations to avoid code duplication
- **Streamlit caching**: Use `@st.cache_data` for database queries and data processing to minimize redundant computations
- **Efficient database queries**: Write optimized SQL queries with proper indexing on frequently queried columns (date, exercise_name)
- **Lazy data loading**: Only fetch data when needed (e.g., load chart data only when chart tab is selected)
- **Minimal dependencies**: Keep requirements.txt focused on essential packages only
- **Concise UI design**: Simple, focused interface to reduce rendering overhead
- **Batch database operations**: Use transactions when inserting multiple exercises per session
- **Connection pooling**: Reuse database connections rather than creating new ones for each query
